# 项目区文件映射规范

> 状态：第一版实现与本地小型项目验证中。
> 产品边界见 [Protocol插件与项目区设计](Protocol插件与项目区设计.md)。

## 1. 目标

项目区映射只连接当前 Protocol 工作需要的关键事实：项目规则、任务、理解文档、影响面、验证、人类批准与测试入口。它不是扫描生成的全仓 `INDEX.md`；路径树和相对链接承担导航。

## 2. 目录布局

```text
<project-root>/
├── AGENTS.md
├── .agents/
│   └── protocol/
│       ├── guard.json
│       ├── map.md
│       ├── task.md
│       └── verification/
│           └── understanding-review.md
└── doc/
    └── protocol/
        ├── README.md
        ├── 00-基础调查问卷.md
        ├── understanding/
        │   ├── architecture.drawio
        │   ├── data-flow.drawio
        │   └── naming.md
        ├── impact/
        ├── tasks/
        ├── reviews/
        └── approvals/
            ├── understanding-approved.md
            └── write-exemption.md
```

## 3. 文件职责

| 文件或目录 | 归属 | 职责 |
|---|---|---|
| `AGENTS.md` | 项目根 | 只保留项目区短指针和不可绕过的常设边界。 |
| `guard.json` | `.agents/protocol/` | hook 读取的机器状态；初始化后由守卫保护。 |
| `task.md` | `.agents/protocol/` | 当前任务、权限、验收、人类可兜底边界与升级路径。 |
| `map.md` | `.agents/protocol/` | 连接项目规则、README、构建/测试入口、理解文档、验证与批准。 |
| `verification/` | `.agents/protocol/` | 独立验证方的只读审查结论。 |
| `00-基础调查问卷.md` | `doc/protocol/` | 使用者确认的第一轮前提。 |
| `understanding/` | `doc/protocol/` | 整体架构图、数据流动和命名规范。 |
| `impact/` | `doc/protocol/` | 改动影响面、风险、验证与回滚说明。 |
| `tasks/` | `doc/protocol/` | 可复用的任务级交付与记录。 |
| `reviews/` | `doc/protocol/` | 冷启动回顾和方向偏差结论。 |
| `approvals/` | `doc/protocol/` | 人类签发的理解批准与临时豁免，主施工 agent 不得写入。 |

## 4. AGENTS 短指针

初始化时追加的短指针只应链接：

- `.agents/protocol/guard.json`
- `.agents/protocol/task.md`
- `.agents/protocol/map.md`
- `doc/protocol/README.md`

根 `AGENTS.md` 不应重复问卷、任务细节、架构事实或规程全文。每个事实只在其唯一归属文档维护。

## 5. 映射规则

`map.md` 必须维护下列链接：

1. 项目根和局部 `AGENTS.md`。
2. README、架构/开发文档、构建与测试入口。
3. 当前任务与三项最低理解文档。
4. 影响面、独立验证报告、冷启动回顾。
5. 人类批准或豁免。

路径一律使用相对 Markdown 链接或相对路径。映射内容随已验证事实更新；文件不存在、权限不足或结论未验证时必须明确标记，不得静默删除或伪造成事实。

## 6. 渐进式 draw.io 图谱

整体架构图和数据流动以可编辑 `.drawio` 图谱承载：

```text
全局架构骨架
  → 任务相关模块/服务边界与依赖
  → 任务数据流
  → 按需补时序图、接口/事件、存储和部署细节
```

图中节点和连线区分 `[已验证]`、`[假设]`、`[待确认]`，可在备注或链接中附 README、源码、配置、测试、命令输出或对话确认作为证据。图谱拆分粒度由任务范围、系统复杂度和介入权限决定，不设固定文件数量。

## 7. 项目理解文档更新

只更新本次已验证、对后续介入有价值的事实；不强制为每次小改动额外造文档。目标是避免下一次介入从零猜测，而不是增加文档数量。
